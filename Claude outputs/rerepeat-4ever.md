## 1. Reason — *the ground given for a claim, stated rather than implied*
`2-interpreter-python/ever.py:148` gives every thread a `reason: str`, and `e_z()` at line 213 makes it impossible to mint a Z without one — `docs/SEMANTICS.md` §1 lists ρ as "why it is untrusted, **preserved always**", and the constructor enforces that rather than trusting callers. The good is that the field survives the crossings that matter: `abi_test.py:86` round-trips a particle through the C ABI and asserts `back2.reason == "unverified"` came home intact, so the explanation is part of the value, not a log line beside it. The balance is that ρ is prose — `a_assimilate` writes `f"assimilated {p.lang.name} to {to.name}, ..."` at `ever.py:302`, which reads perfectly to a human and is opaque to a query, so nothing can aggregate *why* a corpus lost trust. And the tests reach for it the only way prose allows, by keyword: `abstract_test.py:45` checks `"x" in rz.reason`, `:71` checks `"2/3" in fp.reason`, `:130` checks `"termination" in gr.reason` — so a reason that degrades into a fluent sentence about the wrong binding still passes, as long as the keyword is somewhere in it.

## 2. Reify — *give an abstraction a concrete representation* (naming, Python phase)
Propose a small `Reason` record — `(code, subject, detail)` — to replace the free string at `2-interpreter-python/ever.py:148` and the keyword assertions in `abstract_test.py` that stand in for checking it. The string was the right first move: `docs/SEMANTICS.md` demands ρ be preserved *always*, and a string is the one representation that never fails to hold whatever a call site knows. The cost is paid at every reader — `E.__repr__` at `ever.py:206` formats it, the tests grep it, and the SQL archive has nowhere to put it, so the most load-bearing explanatory field in the language is the one field no layer can index. Reified, `defect` (already an enum at `ever.py:215`) and `code` would let `4-archive-sql/archive.sql` store *why* a crossing lost confidence rather than only how much, which is the question the archive exists to answer and currently cannot.

## 3. Reflexivity — *a relation every element bears to itself*
`0-atom-c/tapestry.c:183` makes `e_band` total and single-valued on `0..256` — exactly one branch fires per input — and `e_equilibrium` at line 209 is then just `e_band(a) == e_band(b)`, so reflexivity, symmetry and transitivity are consequences of band being a function rather than three separately-tested hopes. That is the strongest design decision in the repo, and `4-archive-sql/zeroth.sql` states the arithmetic that forced it: proximity breaks 969,840 of 4,922,897 triples, so a tolerance relation could never have carried the law. The balance is coarseness — six bands means two confidences 1 apart can land in different equilibrium classes, which is why `same_spectrum` at `ever.py:89` still exists and is documented as *not* the law. `e_equilibrium_survives_crossing` (`tapestry.c:225`, `ever.py:98`) is where that coarseness bites: an unanchored thread pays 1 on every hop, so a value standing on the low edge of its band is demoted by the crossing alone and two threads equal at home disagree abroad — correct by design, and the reason anchoring is the portability mechanism rather than a performance flag.

## 4. Replicate — *reproduce the same thing in another place, deliberately*
The Zeroth Law exists four times over — `0-atom-c/tapestry.c:183` (C), `2-interpreter-python/ever.py:73` (Python), `4-archive-sql/zeroth.sql` (SQL constraint), plus the band table in `zeroth.db` — and `E_DEPTH_CEILING = 3` is redefined independently at `abstract.py:64`, `ir.py:45`, `tac.c:667` and `kitchen_sink.c:71`. This is chosen, not sloppy: `CLAUDE.md` says outright that `E_DEPTH_CEILING` is **not** in `tapestry.h`, local guards only, which keeps `0-atom-c` translation-unit-independent and lets each layer compile with nothing shared. The balance is that agreement then has to be *proved* rather than *structural*, and `tests/test_zeroth.py` does prove it — I ran it directly: Python and C agree on all 257 values, Python and SQL agree on all 257, and all three agree on every boundary. The bad is what happens when that proof stops being read: the suite that carries it is the one `tests/run_all.py` currently mislabels (word 15), so the single mechanical check holding four copies of a law together is also the check most likely to be skipped without anyone noticing.

## 5. Recursion — *a procedure that re-enters itself, counted against a ceiling it must earn*
`2-interpreter-python/scope.py:288` refuses the obvious implementation: `_own_recursion_depth` walks the scope chain counting frames named `f"fn:{name}"` instead of trusting the shared `depth` int, because `depth` measures the whole stack and would punish a non-recursive helper for its anchored caller's five levels. Getting that right is the difference between a depth ceiling and a depth tax, and the docstring at lines 289-303 records the exact bug it prevents. The cost is an O(depth) walk on every call plus a naming convention — `fn:{name}` — that is load-bearing string data, so a frame named wrong silently reports zero own-depth forever. And the two phases still compare differently: `abstract.py:371` gates on `depth > E_DEPTH_CEILING` while `0-atom-c/tac.c:874` gates on `depth >= E_DEPTH_CEILING`, reconciled only by the 0-based/1-based convention `CLAUDE.md` documents and tells you not to "fix" — a convention that lives in prose, which word 7 is about.

## 6. Revert — *put back a previous state, and record that you did*
`0-atom-c/tac.c:858-873` is a revert written into the source: "CORRECTED BACK from a `depth + 1 >= ceiling` version added earlier this session", with the reason — that version was validated only against `ev_interp_call()`, an entry point which skips the very gate being tested. The good is unusual and worth keeping: the comment names the false path, names the real one (`OP_CALL`, how every actual `.ever` program calls), and says the fix was confirmed by full regression rather than an isolated probe. The balance is that this is history stored in a comment rather than in a test — it explains the past to a reader and constrains nothing that runs. Nothing in the repo would fail if someone reintroduced `depth + 1 >= ceiling` and validated it the same wrong way again; `ev_interp_call` at `tac.c:967` still enters at `depth=1` with its own explanatory comment, so the convenient path that caused the bug is still there, still callable, and still unguarded by a test that distinguishes it from `OP_CALL`.

## 7. Reconcile — *bring two separate accounts into agreement* (naming)
Propose `tests/test_ceiling.py` — a reconciliation suite for depth doing precisely what `tests/test_zeroth.py` does for band: run the same `.ever` program through the Python evaluator and the C `OP_CALL` interpreter and assert identical results at the boundary, `fact(3)`=6 and `fact(4)`=z, through `ev_interp_run` rather than `ev_interp_call`. The current arrangement is defensible because `tests/cross_layer_test.py` already reconciles something harder — five languages' parse output, "every case agreed" at line 116 — so the pattern exists and works. But that suite covers translation shape only; grepping it for `depth`, `CEILING` or `fact` returns nothing, so the constant `CLAUDE.md` calls out as the thing "C and Python must agree" on is the one cross-layer claim with no cross-layer test. Today the agreement rests on a 16-line comment in `tac.c` and a warning in `CLAUDE.md`, which is why a `depth + 1` variant could be introduced, tested against the wrong entry point, and shipped green once already.

## 8. Refuse — *decline outright, where a partial answer would mislead*
`2-interpreter-python/emit.py:149` raises `NotImplementedError` if any statement is an `Extern`, before emitting a single line, and the comment at 139-148 earns the strictness: a silently-dropped extern leaves the CALL in the generated code, and for a name that happens to be a target-language builtin — R's own `sqrt()` — it appears to work by coincidence while every other extern fails. Refusing the whole program is the only behaviour that cannot quietly mislead, and 42 occurrences of "refuses" across the repo say this is a house pattern rather than one function's mood. The balance is bluntness: one `extern` makes the program untranspilable to all four backends even if the extern is unreachable, and the raise happens before any partial output a developer could inspect. The check's soundness is also borrowed rather than owned — it scans `prog.statements` only, which is complete *because* `syntax.py:529` admits `Extern` at top level alone; loosen the grammar to allow an extern inside a function body and this line stops seeing it, with no test in `emit.py`'s suite pinning that dependency.

## 9. Retain — *keep hold of; own for a bounded lifetime*
`0-atom-c/ir.h:40-57` states arena ownership as five numbered rules and the API keeps them: `ev_arena_alloc` is the only allocator, callers may read but never free, cross-language boundaries copy rather than alias, and `ev_arena_free` releases everything in one call. Bump allocation plus one owner per parse/execute cycle is why raw `EvNode` pointers can cross the ABI at all — there is no GC race to lose, and `kitchen_sink.c` runs clean under ASAN for exactly this reason. The balance is that retention is all-or-nothing: `EV_ARENA_SLAB_SIZE` × `EV_ARENA_MAX_SLABS` (`ir.h:76-77`) caps a cycle at 4 MB with no partial release, so a long-lived interpretation has a hard ceiling rather than a growth path. RULE 1 also has an exception the header does not name — `tac.c:571` and `tac.c:610` call `calloc` directly for pass scratch (both freed, at 603 and later) — which is defensible as pass-local temporaries, but means the one rule stated as absolute is enforced by reading rather than by anything mechanical.

## 10. Relinquish — *give up a claim you were handed* (naming, C phase)
Propose dropping the fourth parameter: `ev_lower_module(const char *name, EvNode *root)`, because `0-atom-c/tac.c:497` already discards it — `(void)arena;` — after minting its own at line 484. The behaviour is right and the comment says why: a fresh arena means `ev_module_free` fully owns the module's memory while the caller's arena, which owns `root`, stays valid throughout. But the signature at `tac.h:303` still advertises an arena it will not use, and `CLAUDE.md` has to carry a landmine note distinguishing `ev_module_new` (TAKES the arena) from `ev_lower_module` (MINTS its own) — a warning made necessary by a parameter that exists only for symmetry with the function it must not be confused with. Worse for a reader following the type rather than the prose: the two functions differ in ownership and agree in shape, which is exactly the pair a caller gets wrong once and double-frees, and `tac.c:490` compounds it by returning a live module with no global body block when `ev_func_new_block` fails, rather than failing the way line 487 does.

## 11. Register — *a record carried back; here, a TAC slot with trust attached*
`0-atom-c/tac.h:145` reserves `EV_REG_VOID = 0` as "no value", so index 0 is never a real register and every `uses[]` write in `ev_pass_dead_regs` lands in bounds by construction rather than by a bounds check. Carrying confidence on the register itself (`tac.h:55`, every `EvReg` has 0..256) is what lets `ev_pass_conf_prop` fold trust without a side table, keeping the optimiser and the semantics in one structure. The cost is a sentinel in-band: 0 is both "not a register" and a valid array index, which works only while nothing allocates id 0. That contract is kept unevenly — `tac.c:579-580` guard `src0` and `src1` with `ev_reg_is_void` before counting, and line 582 counts `ins->args[ai].id` with no guard at all, so a call argument that lowered to void (reachable at `tac.c:434`, where `ev_lower_node` can return void for a child it cannot lower) silently credits register 0 instead of surfacing as a lowering failure: not out of bounds, but unobservable, which is the harder bug to find later.

## 12. Reduce — *fold many values to one, by the weakest*
`docs/SEMANTICS.md` §2.1 fixes chain as `min` — possibilistic, a bound and never a probability — chosen over `c_f × c_x / 256` so a ten-step computation over trusted inputs stays above the execute floor instead of collapsing. `0-atom-c/tac.c:267` implements it as the obvious guarded scan (`if (args[i].confidence < conf) conf = args[i].confidence;`), which is right, cheap, and reads as the spec. The spec also states the cost plainly, which is rare: `min` does not track accumulated independent error, so a hundred-step chain of 200s reports 200 and Ever accepts that and says so. The exposure is duplication of the fold rather than the fold itself — the interpreter reduces at `tac.c:267` and `ev_pass_conf_prop` reduces again at `tac.c:641-642` over `conf[]`, two implementations of one law in one file, and an optimiser whose confidence arithmetic drifts from the interpreter's produces programs whose trust depends on whether the pass ran.

## 13. Repair — *restore a thing to working order, at a recorded cost*
`4-archive-sql/repair.sql` is the strongest instance of the repo's twin-implementation pattern: a repair is a PAIR with neither half empty, cost is DERIVED from kind and never supplied, confidence never rises through a repair (`CHECK (conf_after <= conf_before)`, line 113), and a rejected rule is kept as a boundary marker because nothing is ever deleted. Expressing those as `CHECK` constraints and triggers (`trg_repair_no_rise`, `trg_rule_floor`) moves the invariant from something a caller may forget to consult to something the storage boundary enforces — the file's own framing, and the right one. The balance is that the same contract now exists twice, in SQL and in `7-refix-node/src/archive.js`, and `4-archive-sql/repair_test.py:9` is candid about how they are kept in step: "Every `refuses(...)` case below has a matching throw in `7-refix-node/src/archive.js`" — a promise in a docstring, maintained by hand, with nothing reading both files. And the suite that would catch drift opens by deleting its own subject (`repair_test.py:41`, `os.remove(DB)`), so in the one layer whose stated invariant is that nothing is ever deleted, the tests cannot run at all where the database file is not deletable — which is exactly what happened here, three times, in this run.

## 14. Replay — *run the past again and require it to come out the same*
`7-refix-node/src/archive.js:137` earns the word properly: `_replay` re-checks a proposed rule against every prior repair, sets `replay_total`/`replay_agreed`, and at line 145 refuses admission unless they are equal, with `rejected_why` naming how many priors would change. That is the right gate for a system that learns fixes from observed failures — a rule that would have broken history does not get to shape the future, and unanimity (rather than a majority) is the conservative choice for a corpus this small. It is also strict enough to stall: one disagreeing prior blocks a rule permanently, and since rejected rows are retained as boundary markers rather than re-litigated, a rule rejected on five priors stays rejected after the sixth would have vindicated it. The rise is capped to match — `E_INTAKE` (120) to `E_EXECUTE_FLOOR` (128) and no further from replay alone (lines 151-152) — which is consistent with the language's refusal to let corroboration manufacture certainty, and also means replay can clear a rule for execution while leaving it permanently unverified, with recurrence across distinct sources (`archive.js:95-102`, a `Set` of `source_ident`, threshold `E_ASCEND_POINTS`) as the only path further up.

## 15. Regression — *a fault that returns, and the harness whose one job is to notice*
`tests/run_all.py` runs 34 suites across eight layers and prints a scorecard, and its comment states the correct policy: layers whose toolchain is absent report SKIP, they never report PASS. Two lines undo it. Line 68 classifies by substring — `if "SKIP:" in out` — so any suite whose *output text* contains `SKIP:` is recorded as skipped regardless of its exit code, and I watched this fire: `python3 tests/test_zeroth.py` exits 0 with "16 passed, 0 failed, 1 skipped", and `run_all.py` reports the whole Zeroth Law suite — the proof that four independent copies of `e_band` agree on all 257 values — as SKIP. Line 101 then makes skipping free: `return 0 if not failures else 1`, so a run with 34 skips and zero passes exits 0 and green, while `CLAUDE.md`'s actual gate is "34 passed / 0 skipped / 0 failed" — a standard the harness has no way to report on, let alone enforce. The same substring rule runs the other way too: a genuinely failing suite that prints `SKIP:` anywhere in its output is downgraded from FAIL to SKIP and cannot affect the exit code, which is a green build over a red repo.

## One thought

4Ever's thesis is that a value should carry its trust wherever it goes, and the code delivers that at a level most language projects never reach — band is a total function so the Zeroth Law is structural rather than tested-and-hoped-for, Z carries its reason through the C ABI intact, confidence rides on the TAC register itself, and the archive refuses at the storage boundary what JavaScript refuses in the caller. What does not travel with the same rigor is the *agreement between layers*. `E_DEPTH_CEILING` is replicated four times by design; `e_band` exists four times over; the depth comparison differs between `abstract.py:371` and `tac.c:874` and is reconciled by a convention in `CLAUDE.md`; the SQL and JavaScript repair invariants are held in step by a docstring promising a hand-maintained correspondence; a revert and the false validation path that caused it are recorded in a C comment; RULE 1's exception is unnamed. Every one of those is a claim about two pieces of code that only prose asserts — and prose is exactly what a test suite exists to replace. Which is why the harness is the load-bearing component here rather than a chore: `tests/run_all.py` is the single mechanism that would catch any of these drifting, and it is the one component in the repo that cannot currently report its own result honestly — it downgrades a passing cross-layer proof to SKIP on a substring match, and exits green on a run where nothing passed at all.

**Change first:** `tests/run_all.py` — classify SKIP structurally instead of by substring (a dedicated exit code, or a first-line marker protocol each suite emits), and make `skipped > 0` exit non-zero, so the harness can enforce both halves of the 34/0/0 gate `CLAUDE.md` already demands of every agent.

**Prove it:** On a machine with the full toolchain, `python3 tests/run_all.py` reports **34 passed / 0 skipped / 0 failed** and `tests/test_zeroth.py` — which exits 0 while printing "1 skipped" — shows as PASS. It fails today in both directions at once: that suite reads SKIP on this machine despite exiting 0, and the run exited 0 with 2 skipped and 4 failed.
